# 1 前言

## 1.1 目的和范围

本文档定义中安云科 AI 安全网关管理面的软件需求，作为产品设计、开发、测试与验收的共同依据。

本文档的范围是产品的管理面功能，包括四个部分共九个功能：

- AI 网关部分：模型端点管理、压缩护栏管理、虚拟密钥管理
- 访问控制部分：团队管理、内部用户管理
- 可观测性部分：用量、日志、成本优化
- 设置部分：授权管理

本文档不覆盖以下内容：南向模型接入协议的具体适配实现、计费结算与开票、智能体与 MCP 工具链的独立功能、底层数据库与缓存组件的自身功能。

## 1.3 产品范围

产品定位为企业私有化部署的 AI 安全网关。它在业务应用与大模型服务之间提供统一接入层，把分散在各业务系统中的模型调用收敛到一处，实现统一鉴权、统一配额、统一审计与统一成本核算。

产品价值与业务目标如下：

- 降低接入成本：一套网关同时对接多家模型供应商与自建模型服务，业务侧只改一次接入地址
- 强化安全合规：密钥集中托管与掩码展示，按团队与用户授权，全量调用留痕，离线部署保证数据不出内网
- 控制成本：按模型、团队、密钥、用户多维统计花费，支持预算与限流，提供提示词压缩、缓存与自动路由等降本手段
- 保障商业交付：授权文件与机器码绑定，未授权时业务接口不可用，满足产品商业授权要求

# 2 综合描述

## 2.1 产品的前景

企业内部接入大模型的方式通常有两种：各业务线直接对接供应商 API，或在部门内自建代理脚本。前者导致密钥分散在多个系统、无法统一限流与审计、成本难以归集；后者缺乏统一治理，重复建设。

随着模型供应商增多、模型更新加快、监管对数据出境与调用留痕的要求提高，企业需要一个部署在内网、统一管理、可审计、可计费的接入层。中安云科 AI 安全网关即为此场景设计，采用离线安装包交付，一条安装脚本完成部署，管理面提供完整的中文界面。

## 2.2 产品的组件与功能

产品以容器化方式部署，由以下组件构成。

| 序号 | 组件 | 部署形态 | 主要功能 |
|------|------|----------|----------|
| 1 | 网关服务 | 主容器 | 对外提供模型调用接口与管理接口，承载模型端点、虚拟密钥、护栏、用户、团队、可观测性与授权功能 |
| 2 | 管理界面 | 随网关服务发布 | 中文 Web 管理控制台，浏览器访问 /ui |
| 3 | 关系型数据库 | 数据库容器 | 存储模型、密钥、用户、团队、花费、日志、配置等业务数据 |
| 4 | 缓存服务 | 缓存容器 | 支撑预算计数、会话与并发控制 |
| 5 | 压缩服务 | 压缩容器 | 提供 Headroom 提示词压缩能力，作为压缩护栏后端 |
| 6 | 监控服务 | 监控容器 | 采集网关指标，提供 Prometheus 格式指标与基础看板数据 |
| 7 | 安装与运维脚本 | 宿主机脚本 | 提供安装、卸载、启动、停止、重启、备份、恢复、状态查看等运维命令 |

## 2.3 原系统描述及其存在的问题

原系统指当前企业内各业务系统直接对接模型供应商的方式。其典型形态是每个业务系统自行申请供应商密钥、自行实现重试与计费，缺少统一出口。

| 序号 | 问题 | 影响 |
|------|------|------|
| 1 | 密钥分散在多个系统与配置文件中 | 泄露风险高，轮换成本大，无法统一回收 |
| 2 | 没有统一限流与配额 | 个别业务突发流量影响全局，成本不可控 |
| 3 | 调用无统一留痕 | 出现安全事件或异常时无法定位调用方与请求内容 |
| 4 | 成本按供应商账单归集 | 无法按团队、密钥、用户分摊，成本优化缺少依据 |
| 5 | 各系统重复实现重试、降级、模型切换 | 重复建设，行为不一致 |
| 6 | 无商业授权与合规约束 | 产品化交付缺少授权控制手段 |
| 7 | 界面与文档以英文为主 | 国内运维人员使用门槛高 |

## 2.4 目标系统综述

目标系统在业务应用与模型供应商之间增加统一的 AI 网关。业务应用把请求发往网关，网关按虚拟密钥完成身份识别、权限校验、预算与限流检查、护栏处理，再转发至上游模型服务，并把本次调用的模型、耗时、token 数、花费与调用方信息写入日志。

管理面提供九个功能：模型端点管理维护可调用的模型清单与上游配置；虚拟密钥管理签发与回收调用凭据；压缩护栏管理配置内容检查与提示词压缩；团队管理与内部用户管理维护访问控制主体；用量、日志、成本优化提供多维统计与明细查询；授权管理控制产品的商业使用许可。

方案克服了 2.3 中列出的问题：请求统一出口、密钥集中托管、权限与预算可配置、调用全量留痕、成本多维归集、管理界面中文化、产品授权可控。

局限性说明：

- 产品为单机容器化部署，不提供多节点集群与跨机房容灾能力
- 授权与机器码绑定，更换主机需要重新签发授权
- 可观测性统计按 UTC 自然日分桶，与本地自然日存在时区差异，界面需明确提示
- 产品基于上游开源版本二次开发，上游接口的兼容性受版本约束

## 2.5 用户分类和特征

| 序号 | 用户类别 | 角色标识 | 特征与关注点 | 主要使用功能 |
|------|----------|----------|--------------|--------------|
| 1 | 系统管理员 | proxy_admin | 负责产品部署、账号体系、模型接入与授权，具备全部管理权限 | 全部九个功能 |
| 2 | 只读管理员 | proxy_admin_viewer | 负责查看与审计，不具备增删改权限 | 模型、用量、日志、成本、授权查看 |

## 2.6 运行环境

| 项目 | 要求 |
|------|------|
| 服务器架构 | x86_64 |
| 操作系统 | 麒麟 V10、Ubuntu 22.04 及以上、CentOS 7 及以上等主流 Linux 发行版 |
| 容器运行时 | Docker 26.0.1，随安装包提供离线安装文件 |

| 管理端浏览器 | Chrome 或 Edge 最近两个大版本，分辨率 1440×900 及以上 |
| 时区 | 统一使用 Asia/Shanghai，界面时间按北京时间展示 |
| 默认端口 | 管理面与业务接口 4000、监控 9090、数据库 5432、缓存 6379，均可在安装时调整 |

## 2.7 设计和实现上的限制

- 必须以离线安装包形式交付，解压后执行单一安装脚本完成部署，安装过程不得依赖外网
- 必须使用 Docker 容器化部署，不提供裸机安装方式
- 管理界面必须为中文，时间必须按北京时间以 24 小时制展示
- 必须保留原有模型调用接口协议，业务侧接入方式不做破坏性变更
- 授权校验必须在服务端完成，未授权时业务接口不可用，管理面登录与授权相关接口保持可用
- 数据必须存储在本地，不得向外部上报业务数据与调用内容
- 受上游开源版本约束，界面组件与接口结构以当前版本为准，升级需评估兼容性

## 2.8 假设和依赖

- 客户提供符合 2.6 要求的服务器，具备 root 权限与 Docker 安装条件
- 客户已取得厂商签发的有效授权文件，或在部署后按流程申请授权
- 服务器时间已同步至标准时间，时区设置为 Asia/Shanghai
- 上游模型服务地址从网关所在网络可达，相关凭据有效
- 管理端浏览器可访问网关的 4000 端口
- 数据库与缓存组件随安装包提供，不依赖外部实例

## 3.2 功能分解

### 3.2.1 F-01 模型端点管理

| 1 | 上游模型服务 | HTTPS / OpenAI 兼容协议 | 网关按模型端点配置转发请求，支持主流云厂商与自建模型服务 |
| 2 | 关系型数据库 | PostgreSQL 协议 | 存储业务数据，由产品容器提供 |
| 3 | 缓存服务 | Redis 协议 | 预算计数、会话与并发控制 |
| 4 | 压缩服务 | HTTP | Headroom 提示词压缩，供压缩护栏调用 |
| 5 | 监控服务 | HTTP | 采集指标，提供 Prometheus 格式数据 |
| 6 | 授权库 | 本地动态库 | 读取授权状态、生成申请码、导入授权文件 |

产品对外提供的接口分为三类：

- 业务调用接口：/v1/chat/completions、/v1/embeddings、/v1/models 等 OpenAI 兼容接口，以及智能体相关 /v1/a2a 接口
- 管理接口：/key、/user、/team、/model、/guardrail、/config 等管理面接口
- 授权接口：/product/license/info、/product/license/request-code、/product/license/upload 等

## 4.4 通信接口

| 项目 | 说明 |
|------|------|
| 协议 | HTTP/1.1，HTTPS 由前置代理或负载均衡提供 |
| 端口 | 管理面与业务接口 4000，监控 9090，数据库 5432，缓存 6379，均可配置 |
| 编码 | 请求与响应使用 UTF-8 |
| 时区 | 服务端固定使用 Asia/Shanghai |
| 会话 | 管理界面基于令牌鉴权，令牌按产品安全策略设置有效期 |

# 5 目标系统的实施影响

| 序号 | 影响面 | 说明 | 应对措施 |
|------|--------|------|----------|
| 1 | 业务应用接入方式 | 原直连供应商地址需改为网关地址，使用网关签发的虚拟密钥 | 提供接入示例与切换清单，分批灰度 |

| 3 | 密钥管理 | 原供应商密钥收敛到网关的模型端点配置中 | 轮换并回收原业务侧密钥 |
| 4 | 成本核算 | 账单由供应商账单改为网关统计，统计按 UTC 自然日分桶 | 明确统计口径，按团队与密钥分摊 |
| 5 | 运维方式 | 由各系统自行维护改为统一运维 | 使用产品运维命令，建立备份与巡检机制 |
| 6 | 历史数据 | 历史调用日志不迁移到网关 | 保留原系统日志备查 |
| 7 | 授权管理 | 产品使用受授权约束，更换主机需重新签发授权 | 部署前确认授权流程与责任人 |
| 8 | 停机窗口 | 首次切换需要短暂停窗口 | 选择低峰期切换，保留回退方案 |

# 6 设计标准

## 6.1 性能规格说明

| 序号 | 指标 | 目标值 | 说明 |
|------|------|--------|------|
| 1 | 管理界面登录响应 | ≤ 2 秒 | 局域网环境 |
| 2 | 列表页首屏加载 | ≤ 3 秒 | 千级数据量 |
| 3 | 日志查询响应 | ≤ 5 秒 | 最近 7 天范围，万级记录 |
| 4 | 用量统计刷新 | ≤ 5 秒 | 最近 30 天范围 |
| 5 | 模型转发附加延迟 | ≤ 50 毫秒 | P95，不含上游处理时间 |
| 6 | 并发管理操作 | ≥ 10 个会话 | 常规运维场景 |
| 7 | 业务并发能力 | 按部署规格标定 | 不低于同规格直连上游的 80% |

## 6.2 环境规格说明

运行环境要求见 2.6。部署形态为单机容器化，全部组件由安装脚本创建，容器使用数据卷持久化数据，默认随宿主机启动。

## 6.3 兼容性标准

| 序号 | 兼容项 | 要求 |
|------|--------|------|
| 1 | 浏览器 | Chrome、Edge 最近两个大版本 |
| 2 | 分辨率 | 1440×900 及以上，最小支持 1280×720 |
| 3 | 操作系统 | 麒麟 V10、Ubuntu 22.04 及以上、CentOS 7 及以上 |
| 4 | 架构 | x86_64 |
| 5 | 上游接口 | 兼容 OpenAI Chat Completions、Embeddings 等常用协议 |
| 6 | 数据兼容 | 数据库结构随版本升级自动迁移，升级过程需备份 |

## 6.4 标准及法律法规要求

- 产品部署在企业内网，业务数据与调用内容不出内网，符合数据本地化要求
- 调用日志保留期限按客户制度配置，满足审计与追溯要求
- 密钥与密码采用不可逆存储或加密存储，界面展示时掩码处理
- 用户与操作行为记录审计日志，满足等保 2.0 对安全审计的要求
- 开源组件遵循其许可证要求，第三方组件清单与许可证随版本归档

# 8 输入/输出格式

## 8.1 批量邀请用户 CSV

| 列名 | 必填 | 说明 |
|------|------|------|
| user_email | 是 | 用户邮箱，需符合邮箱格式 |
| user_role | 是 | 角色，取值 proxy_admin、proxy_admin_viewer、internal_user、internal_user_viewer |
| teams | 否 | 团队 ID，多个以逗号分隔 |
| max_budget | 否 | 最大预算，数值 |
| budget_duration | 否 | 预算周期，例如 30d、1mo |
| models | 否 | 可用模型，多个以逗号分隔 |

文件格式为 CSV，编码 UTF-8，首行必须包含必需列，单文件大小不超过 5 MB。

## 8.2 团队导出 CSV

字段包括团队别名、团队 ID、组织 ID、模型、最大预算、预算周期、预算重置时间、花费、TPM 限制、RPM 限制、成员预算、成员预算周期、成员 TPM、成员 RPM、成员数、密钥数、是否封禁、创建时间。未配置模型时模型列为空。

## 8.3 授权文件

授权文件由厂商签发，为二进制文件，扩展名 .lic。上传后系统校验文件有效性与机器码匹配关系，校验通过后授权状态变为正式授权。授权状态持久化在宿主机数据目录。

## 8.4 请求日志字段

请求日志包含时间、类型、状态、会话 ID、请求 ID、费用、耗时、TTFT、团队名称、密钥哈希、密钥别名、模型、Token、内部用户、终端用户、标签。无数据的文本字段展示「暂无」，费用为零展示短横线。
